# 经理与正式执教

玩家兼任一家俱乐部的经理和一线队主教练。本阶段打通接手球队、正式比赛执教、查看赛果、继续赛季及跨年，沿用现有赛事和比赛引擎。

## 进入方式

首页及 `#manager` 打开经理模式。未任职时按赛事体系、联赛级别和俱乐部选择球队。接手沿用当前赛季日期和已有赛果，不重置存档。本阶段一个赛季存档只对应一家执教俱乐部，尚不支持辞职或更换雇主。

经理首页显示本队联赛排名、积分、可用球员、下一场对手、近期赛果及后续赛程。默认赛季目标按本级别球队的首发平均能力分档生成；这里只评估联赛名次，没有董事会谈判、解雇或资金奖励。

## 执教流程

1. 点击“前往下一场比赛”，其他球队按日期自动比赛，遇到本队比赛立即停止。杯赛、全球杯和附加赛采用已经确定的晋级结果识别本队。
2. 点击“赛前布置”，选择自己的阵型、战术和首发。客场仍只能控制自己的球队；对手保持自动控制。首发必须满足现有位置、伤病及本赛事停赛限制。
3. 点击“开始正式比赛”观看逐事件比赛，可暂停、调整战术和换人；也可“委托至终场”。委托使用当前阵容和战术以及引擎已有伤退处理，不包含新增的智能助教轮换策略。
4. 终场赛果直接写入正式赛程、积分榜及球员体能、伤病、停赛记录。回到经理首页继续推进，不会重复结算。
5. 全年赛历完成后进入下一赛季，执教俱乐部、战术和首发偏好延续；实际升降级、全球杯资格和新赛季目标同步更新。伤停球员的首发位置会自动补位。

比赛中心的日期推进同样会在本队赛前停住，不能绕过执教入口自动完成本队比赛。友谊赛继续独立运行。

## 存档

- 在原有赛季 IndexedDB 记录中增加可选的 `manager`、`activeMatch` 字段，兼容尚未任职的原版赛季存档。
- 赛前阵型、战术和首发修改自动保存。正式比赛每批事件与临场指令事务保存后才显示新进度；刷新恢复最近一次成功保存的状态并暂停播放。
- 比赛快照包含随机游标、事件、换人资格集合、体能及球队战术。恢复不重新抽取比赛结果。
- 多页面写入沿用浏览器锁，并核对比赛 ID 与递增序号；过期页面不能重复提交进度或赛果。保存失败时不显示尚未写入的新进度，可刷新后继续。
- 切离比赛页面停止播放，已保存的正式比赛保留；友谊赛仍不作为正式赛季保存。

## 当前范围

个人训练安排、随赛历的能力成长和年度记录已接入，见[球员成长与校准](../football/球员成长与校准.md)。合同、工资预算、转会、实际选秀选人、青训招生、自动退役、士气关系和董事会交涉尚未接入。本阶段不声称已完成完整经理经营系统。

沿用现有比赛中止边界：不足七人时需要赛事裁决，目前不自动判定弃权比分。比赛引擎仍是逐事件概率模型，球场为位置示意。

## 验证

`tests/career.test.mjs` 覆盖旧存档、任职、主客场指挥权限、比赛随机状态恢复、重复提交、伤停首发、赛前布置保存以及托管赛季和跨年。赛季测试中本队采用真实比赛引擎，其他球队采用确定性测试赛果；不把该测试宣称为全世界真实比赛校准。
