# 青训系统实现

入口：接手俱乐部后，侧栏进入“青训中心”。现有存档在当前日期接入，既有球员的身份和初始属性不变。

## 已接入的流程

- 每年每队生成 3 名新青年，分别从 15、16、17 岁开始。首版用少量代表球员维持长期人员更替，没有在后台生成十亿人口，也没有把正态分布前 1% 直接当作职业球员。
- 地方俱乐部青年可以留队培养、17 岁后提拔或外租、释放后寻找新的球队。AI 定期按已表现能力、位置需求和出场情况处理去留，不读取隐藏潜力。AI 主动外租或释放一线队门将时，离队后至少保留两名天然门将；玩家主动操作仍遵循一名门将的最低限制。
- 皇家学院学生与职业俱乐部的归属分开。职业队可以观察，不能直接提拔或安排训练；学生 18 岁后进入每年 1 月 20 日的选秀，球队取得一年签约权，再决定是否签约。
- 租借实际改变比赛注册：球员加入接收球队的一线队名单，由该队的比赛选人决定出场。租期结束归队，外租本身不保证比赛分钟。
- 青年及自由球员在 2—11 月获得按周生成的青年/业余比赛机会。青年与背景队友按位置竞争 11 个首发和最多 5 个替补名额，每场全队合计 990 分钟；没有入选的青年不计比赛经验。伤停按比赛当天判断，青年与正式比赛分钟分别记录；转入一线队后停止补算青年比赛。
- 同一天已经参加青年或成年比赛的球员，流转后不能再踢第二场。角色转换不会重复累计比赛经验。
- 年度更替包含补位和退役。默认外场 37 岁、门将 40 岁开始处理退役；AI 尝试补至至少 18 人、2 名门将，受可签球员和入队名额限制。玩家队只在最低参赛人数不足时提拔现有地方青年，无法补位则延后退役并留记录。

上述年龄、人数、日期是游戏规则参数，并非现实足球的统一制度。

## 生成和成长

当前能力来自已有训练积累、年龄、成熟早晚、相关联的技术/身体/意识等禀赋及个人差异。青年没有职业比赛记录，但可以有此前青训经历。新生代还包含传球、控球、终结、防守等专项倾向；角球、任意球、点球采用不同既往练习分布，门将技术基础按技能区分，见[专项生成调整](专项生成调整.md)。

隐藏发展档案在生成时固定，包含各项属性的发展上限、成熟偏移、学习效率和初始训练积累。潜力是这些属性上限在参考位置上的综合投影；最终能力还受培养和出场影响。改位置不会刷新成长空间。原有一线队球员保留旧成长算法，新增青年使用新算法。

玩家看到当前能力、历年变化、出场经历和发展观察。观察报告根据已发生的成长与比赛记录估计成年能力范围，不直接读取隐藏潜力。同日反复观察不会重抽；至少间隔 14 天且有新证据才可更新，更新不会保证预测一定更准确。

## 培养决策与恢复

地方俱乐部可以选择均衡轮换、优先培养或优先竞争。选人使用已表现能力、年龄、位置适配、身体状态与日期固定的轮换差异，不读取隐藏潜力。每年保存的 3 人是重点观察名单，青年队其余位置由不保存完整生涯的背景球员参与竞争。

每队最多 2 名地方青年列为重点培养，训练指导倍率增加 8%，其余青年减少 2%。球队基础培养质量按所在联赛级别与固定俱乐部差异温和调整。安排次日生效、按日期留历史；提拔或离队后释放名额。这是有限指导时间的抽象，没有加入设施建造或青训财政。

新生成青年逐日累计疲劳，成年后仍沿用这一记录。短期高负荷增加有效训练量，持续高负荷逐步损害训练效率；轻量负荷恢复更快，正式和青年出场增加疲劳。疲劳还降低正式比赛输入的体能。已知比赛临近时，高负荷收益降低；界面提供建议，玩家自行修改训练计划。每日剂量与青年比赛按相同顺序结算，分段推进和读档续跑结果一致。

原有一线队球员保留旧成长曲线，不展示不适用的新恢复建议。没有给旧档补造过去的疲劳或近期出场；新记录从继续推进后开始积累。没有新增随机训练伤病。

## 角色机会与人才流动

正式比赛的 AI 已按公开属性、位置与体能选阵，并进行接近实力的轮换和常规换人。外租按本次注册以来的实际出场与目的队岗位竞争评估；已签约球员可以通过受约束的 AI 招募向更高级别流动。经理的首发、换人及本队人员处置权保留。具体规则与边界见[角色机会与人才流动](角色机会与人才流动.md)。

正式报名/预备队与冷热档案已有独立设计，尚未启用新存档格式或新报名规则。

## 存档和验证

`playerRegistry` 保存新增球员、实际归属、培养路径、选秀签约权、观察报告、流转历史及青训培养计划；`development` 保存属性变化、训练、疲劳、近 7 日出场、正式及青年出场。青年年龄以入库日期为参考，周年计算统一处理闰日。旧存档不追补新青年的历史成长。

验证命令：

```sh
npm run check
npm test
npm run audit:youth
npm run audit:body
npm run audit:specialties
npm run audit:academy-career
npm run audit:academy-world
```

当前 `npm run check` 和 154 项自动化测试通过。回归覆盖生成稳定性、属性关联、潜力隐藏、年龄、重复推进、伤停分段一致性、真实租借名单、当天重复参赛、皇家学院权限、选秀、退役、观察证据、存档恢复与损坏存档拒绝。上一轮的三季经理情景、二十季固定版本基线，以及门将保护修复后的单季回归，保留在[青训长期验证](青训长期验证.md)，不混作本轮结果。

角色机会与流动修复后，从同一初始世界重新完整运行二十季：95,180 场正式比赛、零引擎失败；两次无健康门将告警来自同队两名门将在同一杯赛先后受伤。另完成三季经理情景：14,277 场正式比赛，其中 127 场通过经理入口执教，零可用性告警与引擎失败。末季固定 4-3-3 星冠首发能力由旧版 72.69 提升至 78.71；CA≥80 的职业新生代中，全年不足 450 分钟者由 26/239 降至 4/287。完整口径、原始证据与剩余问题见[青训机会与流动验证](青训机会与流动验证.md)。

浏览器使用独立端口测试存档，检查接手俱乐部、观察保存、刷新恢复、外租、接收队正式名单、球员档案和页面布局，控制台无错误。本次追加重点名额、轮换策略与训练负荷的操作及刷新恢复检查。

长期审计拒绝覆盖已有检查点；重复实验需以 `-- --out 新目录` 指定独立输出，原版本断点续跑使用 `-- --resume`。只有源码哈希与原参数一致才能续跑，避免混合不同规则的结果。

## 本版边界

本轮二十季复测确认了机会与人才流动改善，但末季星冠能力 78.71 仍低于初始 83.34，位置储备不足球队仍为 75 支，完整赛季逻辑存档约 234 MiB。培养玩法可进入内测，长期人才平衡尚未完成；不能用零引擎中断替代长期平衡验收。正式报名/预备队与冷热档案仍仅为独立设计，尚未解决这些结构性限制。

- 青年比赛为成长机会模拟，没有完整青年联赛积分榜、比赛引擎回放或逐球数据。
- 青年已加入随年龄变化的身高、体重及旧档平滑迁移，见[青少年身体发育](青少年身体发育.md)。尚未加入营养、伤病对体重的影响、可建设的青训设施和完整的家庭/教育退出因素。
- 负荷已反馈到新生代的训练效率和正式比赛体能；青年选人暂不直接读取持续疲劳，AI 默认标准负荷，尚未主动按赛程调整训练。
- 25 名 21 岁以上球员、40 人总名单限制新增签约、提拔和租入。已有球员满 21 岁不会自动解约；正式报名和预备队名额制度尚未分离。
- 每年固定 3 人且初始年龄混合，是首版规模控制。未校准现实青训参与人数、职业转化率、位置供需、俱乐部财力或长期顶级球星产出。

新模型的分布和对照实验见[新青训模型校准](新青训模型校准.md)。它验证内部机制，不代表已经拟合真实足球人口。
